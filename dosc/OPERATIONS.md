# Запуск, эксплуатация и восстановление

## 1. Модель установки

Установка состоит из двух частей:
1. отдельный архив с portable Python, CosyVoice core, ML-библиотеками, моделями, FFmpeg и инструментами;
2. Git-код Stream TTS Studio, который накладывается поверх подготовленной основы.

Portable-окружение изолировано; приложение не должно зависеть от системного Python или произвольно установленных системных библиотек. При обновлении кода не обновлять runtime архив автоматически.

## 2. Запуск

Корневой `start_server.bat` запускает `cosyvoice3\upy\python.exe` с `server\app.py`. Это ожидаемая схема текущей поставки. Не заменять путь на `python` из PATH и не переписывать команду запуска без отдельного тестирования на копии установки.

Backend по умолчанию доступен на `http://127.0.0.1:8765`; Dashboard — `/dashboard`, Overlay — `/overlay`. Для OBS Browser Source использовать текущий URL и параметры, настроенные в рабочем профиле.

## 3. Данные, которые нужно сохранять

| Путь | Назначение |
|---|---|
| `characters/` | Голосовые референсы и аватары |
| `server/config.json` | Host, port, параметры генерации и browser flag |
| `server/presets.json` | Персонажи/темы |
| `server/active_character.json` | Активный персонаж |
| `server/da_config.json` | Настройки DonationAlerts/Streamer.bot |
| `server/da_tokens.json` | OAuth tokens — секретные данные |
| `server/temp/` | Временные аудиофайлы |
| `server/fonts/custom/` | Пользовательские шрифты |
| Отдельный portable archive | Python, модели, core и инструменты |

Расположение может зависеть от версии/сборки. Перед копированием сверять фактические пути установки. Не коммитить пользовательские конфиги, токены, голосовые файлы или модели в публичный репозиторий.

## 4. Безопасная процедура обновления

Перед каждым обновлением:
1. Завершить текущий эфир и штатно остановить приложение.
2. Сделать копию всей рабочей папки или как минимум кода, runtime-конфигов, `characters/`, пользовательских шрифтов и portable archive (если обновляется отдельно).
3. Зафиксировать текущие версии/хеши portable archive и текущий commit кода.
4. Накатить только небольшой набор изменений приложения из проверенной ветки `dev`.
5. Запустить приложение тем же BAT-файлом.
6. Выполнить smoke checklist ниже.
7. Только после успешной проверки использовать обновление в эфире.

Не обновлять одновременно код приложения и portable runtime: иначе при регрессии будет трудно определить источник. Для обычного изменения кода portable archive должен оставаться неизменным.

## 5. Smoke checklist перед эфиром

- [ ] BAT запускает portable Python и backend без ошибок.
- [ ] Dashboard открывается, список персонажей и настройки загружаются.
- [ ] Выбор персонажа сохраняется и применяется.
- [ ] Тестовая генерация возвращает корректный WAV.
- [ ] Streamer.bot action отправляет запрос и воспроизводит WAV.
- [ ] OBS Browser Source подключается к Overlay.
- [ ] Тестовая реплика отображается с нужной темой, аватаром и анимацией.
- [ ] Текст с символами `< > & " '` отображается буквально, не как HTML.
- [ ] DonationAlerts подключается, тестовое событие проходит в Streamer.bot.
- [ ] Нет ошибок в логах и заметного роста задержки генерации.

Проверки DonationAlerts выполнять с тестовым событием, а не реальным донатом, если доступен такой режим.

## 6. Откат

Если smoke test не пройден:
1. остановить backend;
2. вернуть предыдущую копию кода целиком;
3. восстановить конфиги/данные только если они были изменены миграцией;
4. оставить portable archive прежним;
5. повторить smoke checklist на прежней версии.

Не удалять и не пересоздавать персонажей, токены или JSON при откате исправления, если конкретное изменение не требовало миграции.

## 7. Логи и журналы

- `logs/studio.log` — основной лог приложения с ротацией (2 MiB, 3 backup-файла).
- `logs/streamerbot_failed_donations.jsonl` — неудачные передачи донатов в Streamer.bot; не публиковать файл без проверки на персональные данные.
- JSON-хранилища поддерживают одно поколение резервных копий `*.bak`; временные `*.tmp` создаются рядом с целевым файлом и удаляются после операции.

## 8. Диагностика

- Backend не стартует: проверить наличие portable Python по ожидаемому пути и целостность runtime archive.
- Модель не загружается: сверить версии и файлы portable CosyVoice/PyTorch/CUDA с известной рабочей сборкой.
- Ошибка генерации: проверить персонажа, voice reference, свободную VRAM и временные каталоги.
- Не работает Overlay: проверить URL Browser Source, локальный порт и WebSocket.
- Не проходят донаты: проверить OAuth status, соединение DonationAlerts и доступность Streamer.bot `/DoAction`.
- FFmpeg операция не работает: проверить portable FFmpeg и его путь внутри runtime archive.

## 9. Ограничение сетевой экспозиции

Сохранять bind на `127.0.0.1`, если нет явной необходимости в LAN-доступе. Не выставлять API в интернет. Любое изменение host/CORS/auth проверять отдельно со всеми локальными клиентами.


## Новый монитор и завершение работы

- Для обычного запуска используйте `start_studio.bat`. Он запускает тот же backend через `pythonw.exe` и открывает локальное окно мониторинга.
- Для диагностики и резервного запуска используйте прежний `start_server.bat`: консольный вывод и автоматическое открытие Dashboard сохраняются.
- Закрытие окна монитора не останавливает backend. Dashboard можно открыть отдельной ссылкой в мониторе.
- Для штатного завершения нажмите «Выключить студию». Команда принимается только при loopback-адресе клиента и Host, чтобы не допустить вызов через DNS rebinding. Uvicorn прекращает принимать новые подключения, ожидает завершения активных запросов в пределах graceful timeout и вызывает shutdown-хук DonationAlerts worker.
- Если новый запуск не открыл окно, проверьте `logs/startup.log` (ранние ошибки запуска и traceback) и `logs/studio.log` (журнал приложения). Загрузчик показывает системное сообщение с путём к `startup.log` при критическом сбое. При необходимости используйте резервный BAT. Не запускайте оба BAT одновременно.

- При старте на Windows создаётся именованный mutex. Повторный запуск обнаруживается до загрузки CosyVoice, чтобы не создавать второй экземпляр модели и не занимать дополнительную VRAM.
