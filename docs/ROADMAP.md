# План безопасной реализации улучшений

## Цель и неизменяемые условия

Цель — устранить конкретные риски и повысить устойчивость, **не нарушив работающую генерацию и интеграцию OBS + Streamer.bot**.

Неизменяемые условия:
- не менять portable archive, portable Python, CUDA, PyTorch, CosyVoice, модели и версии runtime;
- сохранять совместимость обоих способов запуска: рекомендуемый `start_studio.bat` (Launcher/tray) и резервный `start_server.bat` (консольный backend);
- не менять существующие REST routes, методы, JSON-поля и типы ответов без отдельного согласования;
- не менять WebSocket endpoint/event schema и OBS Browser Source URL;
- не менять генерируемые C# Actions, Streamer.bot endpoints и воспроизведение WAV;
- не менять пути/форматы конфигов, персонажей, голосовых референсов и тем без обратимой миграции;
- не внедрять изменения во время эфира.

## Этап 0 — зафиксировать рабочий baseline (обязателен)

**Изменения приложения: отсутствуют.**

1. Сохранить резервную копию текущей рабочей установки и пользовательских данных.
2. Зафиксировать commit кода, хеш/версию portable archive, версию моделей и фактическую конфигурацию host/port.
3. Записать контрольные сценарии: Dashboard, генерация короткого и длинного текста, несколько персонажей, Streamer.bot WAV playback, Overlay preview, OBS Browser Source, DonationAlerts test event.
4. Замерить обычное время генерации и убедиться, что baseline проходит.
5. Подготовить копию установки для испытаний; не тестировать изменения впервые на эфирном ПК во время трансляции.

**Выход:** воспроизводимый чек-лист и точка отката.

## Этап 1 — безопасный рендер текста Overlay (первый кодовый шаг)

Изменить только `web/overlay/overlay.js`:
- убрать интерпретацию внешнего текста как HTML;
- использовать DOM nodes и `textContent`;
- сохранить все существующие режимы анимации, классы, CSS, порядок слов, длительности и fallback;
- не менять формат WebSocket payload и backend.

Проверки:
- обычный русский/английский текст;
- символы `< > & " '`, emoji, переносы строк;
- payload вроде `<img src=x onerror=alert(1)>` отображается как буквальный текст;
- каждый режим анимации, тема, аватар и preview работают как раньше;
- OBS Browser Source отображает текст и очищает предыдущую реплику.

**Откат:** вернуть только предыдущую версию overlay.js.

## Этап 2 — безопасный OAuth callback

Изменить только формирование HTML callback:
- экранировать все внешние значения, попадающие в HTML;
- сохранить route, query semantics и понятный результат для пользователя.

Проверить успешную авторизацию, отказ/ошибку OAuth и строки с HTML-символами. Откат — один файл.

## Этап 3 — защита DonationAlerts secret без потери сохранённой настройки

Изменить backend response и Dashboard UI согласованно:
- GET не возвращает фактический `client_secret`, только статус наличия;
- пустое поле в UI при загрузке означает «секрет уже сохранён», а не «удалить секрет»;
- новый секрет записывается только при явном вводе/замене;
- существующий сохранённый secret/token не очищается обычным сохранением других настроек.

Перед изменением сохранить копию `da_config.json` и `da_tokens.json`. Проверить: открыть настройки, изменить несекретное поле, сохранить, перезапустить, проверить OAuth refresh и тестовый donation flow. Не менять имена ключей на диске без необходимости.

## Этап 4 — OAuth state

Добавить одноразовый случайный state с TTL, проверять его в callback и удалять после использования. Проверить обычную авторизацию, отказ, повторный callback, истёкший/неверный state и перезапуск. Если callback flow использует несколько окон/вкладок, проверить параллельные попытки.

## Этап 5 — лимиты и валидация аудио

Сначала измерить реальные размеры/длительности файлов, используемых в штатном workflow. Установить разумные configurable ceilings с понятными сообщениями об ошибках. Проверять параметры до чтения/тяжёлой обработки; сохранять допустимые рабочие диапазоны. Не менять sample rate, качество, нормализацию и формат WAV как часть этой задачи.

## Этап 6 — локальная API защита и CORS (только после инвентаризации клиентов)

Составить таблицу вызовов: Dashboard, Overlay, Streamer.bot, OBS, preview, внешние локальные скрипты. Зафиксировать origins, WebSocket handshake и сценарий автоматической передачи credentials. Затем минимально ограничить CORS и, если необходимо, добавить локальный токен с безопасным хранением и прозрачной передачей всем клиентам.

Не вводить токен, пока не доказано, что он не потребует ручных действий во время каждого эфира. Сначала тестировать на копии установки. Сохранить loopback bind.

## Этап 7 — условные улучшения и сопровождение

- Синхронный I/O worker менять только при измеренной задержке/блокировке; сохранять таймауты, retry, reconnect и порядок событий.
- **Выполнено:** структурное разделение backend завершено (этап S7): маршруты вынесены в `server/studio/routes/`, общая логика — в `server/studio/core/` и `server/studio/services/`; `server/app.py` оставлен bootstrap/entrypoint. Регрессионные тесты фиксируют HTTP/WebSocket route contract и граф импортов. Новое разделение модулей рассматривать только при конкретной необходимости и с отдельными тестами.
- Зафиксировать inventory portable archive отдельно (версии Python, CUDA, PyTorch, CosyVoice, FFmpeg, модели).
- **Выполнено:** настроен GitHub Actions CI для compileall, pytest и JavaScript syntax checks. GPU/runtime-интеграционные проверки по-прежнему выполняются отдельно в целевой Windows-среде.

## Правила релиза каждого этапа

1. Один логически цельный набор изменений — отдельный commit в согласованной рабочей ветке (сейчас `dev_test`).
2. До изменения — baseline tests; после — те же tests плюс новые регрессионные.
3. Сверить diff: никаких незапланированных изменений runtime, API, JSON schema или generated actions.
4. Smoke test по [OPERATIONS.md](OPERATIONS.md).
5. Только после успешного теста переходить к следующему этапу.
6. Не объединять несколько этапов в один большой PR. Не мержить в `main` автоматически.

## Критерии приёмки

- Все существующие пользовательские сценарии проходят до и после изменений.
- Генерация WAV и её latency не ухудшились сверх заранее согласованного допуска.
- Streamer.bot получает тот же ответный формат и воспроизводит аудио.
- OBS Overlay сохраняет визуальный вид/анимации и корректно отображает произвольный текст как текст.
- DonationAlerts сохраняет авторизацию и доставку событий; secret не раскрывается в GET.
- Конфиги, персонажи, референсы и пользовательские темы сохранены.
- Проверки проведены на копии реальной portable установки до использования в эфире.
