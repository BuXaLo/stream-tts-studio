# AGENTS.md — правила для AI-агентов и разработчиков

Репозиторий **BuXaLo/stream-tts-studio**: локальное Windows-приложение (TTS на CosyVoice 3 + OBS + Streamer.bot + DonationAlerts). Приоритет: сохранить рабочий функционал и данные пользователя.

## 1. Что в репозитории

- Только код Studio. Portable Python, CosyVoice, ML-библиотеки, модели и FFmpeg поставляются отдельным архивом и в checkout отсутствуют.
- Не ставить зависимости в системный Python, не менять версии Python/CUDA/PyTorch/CosyVoice/моделей, не трогать runtime-архив без прямого поручения.
- Не добавлять в Git модели, бинарники, архивы, аудио и секреты.
- Новые зависимости — только если задачу нельзя решить текущим стеком, с обоснованием.

## 2. Работа по согласованию

- Вопрос, анализ, «посмотри» или «проверь» — не поручение менять. Отвечай описанием, вариантами и планом; код и файлы создавай только после явного «делай».
- Перед применением показывай минимальный diff. Не создавай и не меняй файлы, о которых не просили.
- Не смешивай в одном изменении багфикс, рефакторинг, форматирование и зависимости.
- Не выдумывай поведение: подтверждай кодом или спрашивай.

## 3. Рабочий функционал не ломать

Приложение используется на стримах. Без отдельного согласования не менять:

- `start_server.bat` и запуск через portable Python;
- публичные routes, методы, поля, JSON-ключи, типы и коды ответов; контракт `POST /speak` и формат WAV;
- WebSocket `/ws/overlay` и структуру событий;
- URL и настройки OBS Browser Source;
- генерируемые C# Actions и параметры Streamer.bot;
- OAuth callback и сценарий DonationAlerts;
- форматы и расположение конфигов, персонажей, голосов, аватаров, тем и шрифтов (миграция — отдельным шагом с backup и откатом).

Не удалять функции, настройки, темы и анимации ради упрощения. Не переписывать TTS pipeline, не менять порядок генерации и модель конкурентности. Багфикс, который лишь делает ранее падавший ввод обрабатываемым и не меняет результат для корректного, допустим.

Если изменение контракта необходимо: опиши причину, переходный период, миграцию, тесты и откат, затем жди согласования.

## 4. Git

- По умолчанию работай только в `dev`. Если владелец явно назначил отдельную рабочую ветку (например, `dev_test`), работай только в ней; `dev` и `main` не изменяй без отдельного разрешения.
- Не коммить, не пушь и не мёржи в `main`.
- Без force push, reset, rebase и cherry-pick без явного разрешения.
- Перед началом проверь ветку, чистоту дерева и актуальность `dev`.
- Мелкие логичные коммиты. Без логов, токенов, пользовательских данных и аудио.
- Через GitHub API указывай явно согласованную ветку (`dev` по умолчанию), бери актуальный SHA файла, после записи перечитывай результат.
- Сохраняй кодировку UTF-8 и окончания строк файла (`server/app.py` в CRLF). Не конвертируй и не переформатируй: diff должен содержать только реальные изменения.

## 5. Архитектура

- `server/app.py` — bootstrap/entrypoint: добавление `server/` в `sys.path`, вызов `studio.core.env`, загрузка CosyVoice, создание FastAPI и подключение APIRouter.
- Backend-код находится в `server/studio/core/`, `server/studio/services/` и `server/studio/routes/`. Новые backend-модули размещать внутри `studio/`, не создавать конфликтующие top-level пакеты рядом с CosyVoice.
- Dashboard: `web/dashboard/` (статика, генератор C# в `builder.js`). Overlay: `web/overlay/` (анимации входят в контракт). TTS работает из portable runtime.

## 6. Безопасность

- Внешний ввод недоверенный: чат, донаты, ники, параметры OAuth, загружаемые файлы.
- Пользовательский текст в DOM выводить через `textContent` или создание узлов, не через `innerHTML`; в HTML-ответах экранировать.
- Секреты и токены не возвращать в API, не писать в логи и коммиты. Пустое password-поле при сохранении не затирает сохранённый секрет.
- Проверять OAuth state, тип и размер загрузок (лимиты по реальным сценариям).
- CORS не заменяет аутентификацию. Перед изменением CORS/auth перечисли всех клиентов, включая OBS и Streamer.bot.

## 7. Проверки

- Не заявляй, что запускал тесты или приложение, если не запускал. Отделяй чтение кода от runtime-проверки; mock-тест не доказывает GPU-инференс.
- После изменения повтори smoke-чеклист из `docs/OPERATIONS.md`: то, что работало раньше, должно работать.
- Overlay: проверь HTML-символы (`<img src=x onerror=alert(1)>` должен показаться буквально), эмодзи, переносы строк.
- Интеграции: Streamer.bot Action и воспроизведение WAV, OBS и реконнект WebSocket, DonationAlerts на тестовом событии (не на реальном донате).
- Если затронуты запуск или генерация: smoke-тест на копии portable-установки, не первым делом в эфире. Нет runtime — отметь проверку невыполненной.
- Важные JSON писать атомарно, если это не меняет поведение. Fixtures только синтетические.

## 8. Документация и отчёт

- Документация лежит в `docs/`. При смене поведения обнови нужные файлы: ARCHITECTURE, API, SECURITY, OPERATIONS, AUDIT, ROADMAP.
- Различай: факт из кода, свидетельство владельца, гипотезу, реально выполненную проверку.
- Отчёт: что изменено; что намеренно не менялось; какие проверки пройдены, какие не запускались и почему; риски и откат; SHA коммита.

## 9. Запрещено без отдельного разрешения

Изменять `main`; заменять runtime, модели, CUDA и PyTorch; переписывать TTS pipeline; массово рефакторить `server/app.py` без явного согласования владельца; менять API/WS/Streamer.bot/OBS-контракты и форматы данных; запускать destructive-команды; публиковать секреты; заявлять runtime-успех по одному чтению кода.

**Принцип:** улучшать приложение вокруг проверенного рабочего ядра, а не рисковать эфирным трактом.
