# Отчёт аудита проекта

**Дата:** 2026-11-08  
**Ветка:** `dev` (создана от `main`)  
**Тип:** статический аудит исходного кода и структуры репозитория.

## 1. Резюме

Проект представляет собой функционально насыщенное локальное приложение, но backend и значительная часть логики сосредоточены в одном большом файле (`server/app.py`). Архитектура понятна на уровне пользовательских потоков, однако границы компонентов, контракт API, конфигурация окружения и тестирование недостаточно формализованы.

Наиболее важные замечания:
1. Текст Overlay вставляется в DOM через `innerHTML` в нескольких режимах анимации — риск DOM XSS при попадании недоверенного текста.
2. API не содержит аутентификации/авторизации; CORS разрешает любые origins. При запуске не только на loopback это создаёт существенный риск.
3. GET `/api/da/config` возвращает объект конфигурации целиком, включая `client_secret`; OAuth-токены хранятся в JSON в открытом виде.
4. Нет видимых в репозитории тестов, CI и декларативного списка Python-зависимостей.
5. Синхронные сетевые вызовы `requests` выполняются из async DonationAlerts worker.
6. Валидация размера/типа загружаемых файлов и диапазонов параметров аудио недостаточна.

## 2. Сильные стороны

- Локальный-first подход и запуск по loopback по умолчанию.
- Один экземпляр CosyVoice и блокировка генерации через `generation_lock`.
- Изоляция пользовательских данных персонажей от frontend assets.
- Использование аргументного списка для запуска FFmpeg вместо shell-строки.
- Есть очистка временных файлов в основных аудио-потоках.
- Overlay переподключается после закрытия WebSocket.
- TTS разбивает длинный текст на предложения и сглаживает границы аудиофрагментов.

## 3. Находки

### A-01 — DOM XSS в OBS Overlay
**Приоритет: высокий.**  
**Файл:** `web/overlay/overlay.js`, функции отображения текста.

В режимах `word-fade` и `wavy-text` пользовательский текст конкатенируется в HTML-строку и записывается через `innerHTML`. Текст может поступать от внешних событий чата/донатов через Streamer.bot и DonationAlerts. Специальная HTML-разметка в сообщении потенциально может выполнить скрипт в контексте Browser Source.

**Рекомендация:** строить DOM через `createElement` и `textContent`; не помещать исходный текст в HTML-шаблоны. Добавить регрессионные тесты с HTML payload.

### A-02 — API без аутентификации и wildcard CORS
**Приоритет: высокий при сетевой доступности; средний для строго локального режима.**  
**Файл:** `server/app.py`, CORS middleware и API routes.

CORS настроен с `allow_origins=["*"]`, `allow_methods=["*"]`, `allow_headers=["*"]`. API не проверяет токен/сессию. Маршруты позволяют менять персонажей, загружать файлы, удалять данные и инициировать TTS/Streamer.bot actions. По умолчанию host — `127.0.0.1`, но пользователь может задать иной host.

**Рекомендация:** ограничить origins конкретным локальным UI; добавить случайный локальный API token для изменяющих операций; при bind на LAN требовать явное включение защищённого режима и firewall guidance.

### A-03 — Секрет DonationAlerts возвращается API
**Приоритет: высокий.**  
**Файл:** `server/app.py`, GET `/api/da/config`.

Ответ включает `"config": da_cfg`, а `da_cfg` содержит `client_secret`. Любой клиент, имеющий доступ к endpoint, получает секрет. Дополнительно refresh/access tokens сохраняются в `server/da_tokens.json` без шифрования.

**Рекомендация:** никогда не возвращать secret/token; отдавать только `has_client_secret`; скрывать секрет при чтении и сохранять его только при явном обновлении. Для локальной среды ограничить права файлов и предусмотреть удаление/ротацию токенов.

### A-04 — Нет OAuth state-проверки
**Приоритет: средний.**  
**Файл:** `server/app.py`, `/api/da/auth_url` и `/api/da/callback`.

OAuth authorization URL формируется без параметра `state`, callback не валидирует state. Это снижает защиту от подмены/CSRF OAuth-процесса.

**Рекомендация:** генерировать криптографически случайный одноразовый state, хранить его локально с TTL и проверять в callback.

### A-05 — Синхронный I/O внутри async worker
**Приоритет: средний.**  
**Файл:** `server/app.py`, DonationAlertsWorker.

В `async def run_loop` вызываются синхронные `requests.get/post`; сетевые таймауты до 10 секунд блокируют event loop и могут задерживать WebSocket/другие async задачи.

**Рекомендация:** перейти на `httpx.AsyncClient`/aiohttp либо выносить синхронные запросы в thread executor.

### A-06 — Нет ограничений на загрузки и обработку аудио
**Приоритет: средний.**  
**Файл:** `server/app.py`, upload/audio routes.

Файлы читаются целиком через `await audio.read()` или копируются в temp без явного лимита размера/длительности. Параметры `start/end`, `target_gain`, `shifts`, `speed` нуждаются в строгой валидации. Нулевой или отрицательный интервал обрезки может дать пустой фрагмент; чрезмерные shifts и большие файлы способны вызвать высокий расход RAM/VRAM.

**Рекомендация:** ограничить размер и длительность, проверять формат по содержимому, валидировать числовые диапазоны через Pydantic/Depends, добавить cleanup при ошибках и конкурентный лимит тяжёлых задач.

### A-07 — Риск XSS в OAuth callback HTML
**Приоритет: средний.**  
**Файл:** `server/app.py`, `api_da_callback`.

Параметр `error` и текст ответа OAuth провайдера вставляются в HTML через f-string без HTML escaping.

**Рекомендация:** экранировать вывод через `html.escape` или возвращать шаблон с безопасной передачей текста.

### A-08 — Монолитный backend и загрузка ML при импорте
**Приоритет: средний (сопровождаемость/надёжность).**  
**Файл:** `server/app.py`.

API, модели, хранилище, интеграции и аудиообработка находятся в одном модуле. CosyVoice загружается при импорте модуля, что усложняет тестирование, запуск tooling и обработку ошибок инициализации.

**Рекомендация:** разделить на routers/services/repositories; использовать FastAPI lifespan для инициализации/освобождения ML ресурсов; определить интерфейс TTS engine.

### A-09 — Неявные зависимости и отсутствие CI/tests
**Приоритет: средний.**  
**Наблюдение:** в видимом Git-дереве нет `requirements.txt`, `pyproject.toml`, lock-файла, тестового каталога или workflow CI. Runtime Python расположен в portable каталоге, который не входит в Git tree.

**Рекомендация:** зафиксировать версии прямых зависимостей и provenance portable runtime; добавить smoke tests и CI для статических проверок/не-GPU частей.

### A-10 — Ошибки и диагностические данные
**Приоритет: низкий/средний.**  
Некоторые исключения возвращаются клиенту в `detail` без нормализации, а worker подавляет исключения refresh token и печатает потенциально чувствительный контекст. Нет структурированного логирования и единого correlation ID.

**Рекомендация:** централизовать error mapping, редактировать секреты в логах, добавить уровни/ротацию логов и идентификаторы запросов.

## 4. Ограничения проверки

- Аудит статический: приложение не запускалось, GPU/CUDA, модели и внешние OAuth/WebSocket сервисы не проверялись.
- Не выполнялись нагрузочные, интеграционные и end-to-end тесты.
- Содержимое portable `cosyvoice3/` отсутствует в Git tree и не проверялось.
- Заявления README о версиях PyTorch/CUDA и GPU совместимости не подтверждались независимым тестированием.
- Не выполнялся полный аудит сторонних библиотек и лицензий.

## 5. Приоритетный порядок работ

1. Устранить DOM XSS в Overlay и HTML callback.
2. Не отдавать `client_secret`/OAuth tokens; ввести API access control и ограничить CORS.
3. Ввести лимиты и валидацию аудиозагрузок и параметров.
4. Убрать блокирующий I/O из async worker.
5. Разделить backend по слоям, зафиксировать зависимости.
6. Добавить тесты API, TTS orchestration (с mock engine), OAuth и Overlay payload.
