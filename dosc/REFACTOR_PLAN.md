## S4. DonationAlerts worker

**Куда.** `DonationAlertsWorker` (`run_loop`, `send_to_streamerbot`, `get_access_token`, `refresh_tokens`), `api_test_da_donation`, обработчик тестовой кнопки в `web/dashboard/app.js`.

**Проблемы.** Синхронные `requests` внутри `async` (4–10 с на вызов блокируют весь сервер). Необработанная ошибка (payload не dict, `float(amount)`, `json.loads(action)`) приводит к реконнекту и потере доната. Повторов и журнала нет. При 5xx/429 показывается «Требуется авторизация». Выключение слушателя срабатывает только после следующего сообщения.

- [ ] Все синхронные HTTP-вызовы в `run_loop` обернуть в `await asyncio.to_thread(...)`.
- [ ] `get_access_token` вернуть профиль вместе с токеном, убрать повторный запрос профиля.
- [ ] Вынести `parse_donation(payload) -> dict | None` с проверкой типов (dict, JSON-строка, список, `None`); `amount` приводить безопасно (замена запятой); некорректное событие логируется и пропускается **без реконнекта**.
- [ ] `send_to_streamerbot` возвращает `{success, status_code, error, attempts}`. Payload строить внутри `try`. Повтор **один раз при ошибке установки соединения** (`ConnectionError`) и при HTTP 5xx; при таймауте чтения повтор не выполнять. HTTP 4xx не повторять. Для 5xx владелец согласовал повтор, так как текущий `/speak` формирует WAV до ответа и возвращает 5xx при неудачной генерации. `timeout=(3, 4)`. При не-2xx писать в лог первые 300 символов тела.
- [ ] Неудачные отправки добавлять в `logs/streamerbot_failed_donations.jsonl` (блокировка записи, UTF-8).
- [ ] `/api/da/test_donation` при неудаче отвечает 502 с `detail` (`message`, `status_code`, `error`); в `app.js` разбирать ответ безопасно (не падать на не-JSON) и показывать причину.
- [ ] Backoff реконнекта 5→10→30→60 с, сброс после успешного подключения. Различать: нужна авторизация (401 после неудачного refresh) и DA временно недоступен (сеть, 5xx, 429).
- [ ] Проверка `enabled` без ожидания сообщения: `asyncio.wait_for(ws.recv(), timeout=5)` в цикле.
- [ ] `refresh_tokens`: логировать причину отказа (без секретов), сохранять токены через `write_json_atomic`.
- [ ] `get_redirect_uri` не менять (решение владельца).

**Вне объёма (только по согласованию):** обработка ping-ответов Centrifugo (решать по данным S0); восстановление пропущенных донатов (нужен другой scope и повторная авторизация).

### S4b. Шаблон доната в `builder.js` (согласовать diff)

Только ветка `type === 'donate'`. Последовательность:
1. Обычная попытка (`/speak` с `character`, как сейчас).
2. Повтор через 1,5 с при сетевой ошибке (`HttpRequestException`) или HTTP 5xx; при таймауте **не повторять**. Для HTTP 5xx повтор допустим по текущему контракту `/speak`: генерация WAV завершается до WebSocket-рассылки и HTTP-ответа, а ошибка генерации возвращается как 500 до выдачи WAV. Не добавлять `request_id` и in-memory дедупликацию в студию без новых фактов, меняющих эту оценку. Сохранить в тестах отдельный сценарий ошибки после WebSocket-рассылки, если появится возможность такого отказа.
3. Если студия ответила, но озвучить не вышло: аварийная фраза без текста сообщения («Бухало, тебе пришёл донат от {ник} на {сумма}, но мой код не смог его прочитать»), с тем же `character`, кроме случая 404; она же уходит в оверлей.
4. Если студия недоступна: локальное уведомление (проверить `CPH.ShowToastNotification` в версии Streamer.bot; запасной вариант — `PlaySound` заранее записанного WAV) и запись в журнал. В публичный чат не писать.
5. Журнал только неудачных донатов в постоянной папке (не `%TEMP%`).
6. Таймаут HTTP 90–120 с; результат «неизвестен» при таймауте фиксировать в журнале.
7. Добавить `using System.Threading.Tasks;`. После генерации обязательно нажать Compile в Streamer.bot.

## S7. Разнесение `app.py` (только после S1–S6 и тестов)

Один модуль = один коммит, код переносится **без изменения логики**, имена функций и поведение прежние. Entrypoint и `start_server.bat` не меняются. Порядок импортов сохранить: переменные окружения (`TEMP`, `TORCH_HOME`, `HF_HOME`, …) выставляются **до** импорта `torch`.

server/

      env.py                — пути и os.environ (импортируется первым после bootstrap)

Первым действием в `app.py`, до импорта любых собственных пакетов и `studio.core.env`, выполнить bootstrap стандартными модулями:

```python
import os
import sys
SERVER_DIR = os.path.dirname(os.path.abspath(__file__))
sys.path.insert(0, SERVER_DIR)
```

Это обязательно для embeddable Python: каталог скрипта не добавляется в `sys.path` автоматически. После bootstrap импортировать `studio.core.env`, выставить переменные окружения до импорта `torch`. Существующий `sys.path.append(COSY_DIR)` сохранить без изменения.

Импорты внутренних модулей выполнять через пакет `studio`, например: `from studio.services.text import sanitize_text`. Не создавать `server/core`, `server/services` и `server/routes` как верхнеуровневые пакеты.

В portable runtime в `sys.path` присутствует `cosyvoice` и его подпапки видны как модули верхнего уровня. Поэтому запрещено создавать собственные верхнеуровневые модули/пакеты с именами, совпадающими с подпапками CosyVoice: `utils`, `cli`, `flow`, `llm`, `transformer`, `hifigan`, `dataset`, `tokenizer` и аналогичные. Перед созданием любого нового верхнего import-имени проверять его через `importlib.util.find_spec` именно в portable Python. По текущей проверке имена `studio`, `core`, `services`, `routes`, `tests` свободны, `utils` занято (`cosyvoice/utils`).

Порядок переноса: `studio.services.text` → `studio.core.storage/config` → `studio.core.ws` → `studio.services.da_worker` → `studio.services.audio_tools` → `studio.services.tts_engine` → `studio.routes`. Тесты запускаются только в отдельном dev-окружении. Portable Python 3.10.11 используется для проверки импорта/запуска приложения, а не для установки pytest.
