# Безопасность и модель угроз

## Предполагаемая среда

Приложение предназначено для локального Windows ПК стримера. Backend по умолчанию слушает `127.0.0.1:8765`. Интеграции могут передавать в приложение текст зрителей и донатеров, то есть недоверенный внешний ввод.

## Защищаемые активы

- DonationAlerts client secret и OAuth tokens;
- голосовые референсы и аватары персонажей;
- доступность GPU/CPU и дискового пространства;
- возможность запускать синтез и триггерить действия Streamer.bot;
- содержимое Browser Source Overlay.

## Границы доверия

1. Интернет/чат/донаты → Streamer.bot и DonationAlerts.
2. Streamer.bot → локальный HTTP API.
3. Dashboard в браузере → локальный API.
4. Backend → файловая система и ML runtime.
5. Backend → OBS Browser Source через WebSocket.

Нельзя считать текст чата, доната, имя пользователя, OAuth error или загружаемый файл доверенным вводом.

## Обязательные меры

- Экранировать весь внешний текст; отображать его через DOM `textContent`, не через `innerHTML`.
- Не отдавать секреты через API и не логировать токены/Client Secret.
- Ввести локальную авторизацию API для изменяющих операций и WebSocket; секрет генерировать локально.
- Ограничить CORS только origin Dashboard и не использовать wildcard.
- По умолчанию оставлять bind на loopback; при LAN bind требовать явного предупреждения/защиты.
- Проверять OAuth `state`; использовать одноразовый TTL.
- Ограничивать размер, длительность и формат загружаемого аудио/аватаров/шрифтов.
- Валидировать ID, числовые параметры и URL Streamer.bot; запретить произвольные адреса, если не требуются.
- Хранить конфигурацию и OAuth токены с ограниченными ACL Windows; предусмотреть экспорт/удаление секретов.

## Инцидентный минимум

Если Client Secret или OAuth token оказался в логах/публичном API/репозитории:
1. отозвать или обновить credential у провайдера;
2. удалить секрет из конфигурации и логов;
3. проверить доступ к локальному API и сетевую экспозицию;
4. обновить credentials и проверить повторную авторизацию.
