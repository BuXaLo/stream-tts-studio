# Stream TTS Studio

**Stream TTS Studio** — локальная TTS-студия для стриминга, построенная вокруг **CosyVoice 3**.

Проект объединяет генерацию речи, управление голосовыми персонажами, подготовку голосовых референсов, интеграцию со **Streamer.bot**, **DonationAlerts** и собственный **OBS Overlay** в одном локальном интерфейсе.

Основная задача — превратить локальный voice cloning / TTS в полноценный инструмент для стрима: от сообщения зрителя или доната до готовой озвучки и отображения текста на экране.

---
### Требования к видеокарте

Для работы Stream TTS Studio требуется **NVIDIA GPU с поддержкой CUDA**.

Проект использует **PyTorch 2.7.1 + CUDA 12.8**. Эта версия PyTorch официально включает поддержку Blackwell и CUDA 12.8.

**По архитектурам NVIDIA:**

* 🟢 **RTX 50xx** — Blackwell — поддерживается
* 🟢 **RTX 40xx** — Ada Lovelace — поддерживается
* 🟢 **RTX 30xx** — Ampere — поддерживается
* 🟢 **RTX 20xx** — Turing — поддерживается
* 🟡 **GTX 10xx / Pascal и более старые** — не рекомендуются и не гарантируются для данной сборки PyTorch

> **Важно:** это информация о совместимости CUDA/PyTorch, а не результат тестирования каждой конкретной видеокарты. На данный момент проект непосредственно протестирован на **RTX 5080**.

### Видеопамять

В обычном режиме Stream TTS Studio занимает около **4 ГБ VRAM** в фоне.

Во время генерации дополнительно может потребляться ещё **до ~1 ГБ VRAM или меньше**, в зависимости от текста и текущей нагрузки.

Таким образом, в типичном сценарии приложение занимает примерно **4–5 ГБ видеопамяти**.

При этом необходимо учитывать, что при одновременной работе с игрой TTS и игра используют общую видеопамять видеокарты.

### Использование во время игр

Stream TTS Studio можно использовать параллельно с играми.

На **RTX 5080** приложение без проблем работало в фоне даже при запуске относительно тяжелых игр на **Ultra-настройках**.

Однако не рекомендуется использовать TTS одновременно с играми, которые практически полностью загружают видеокарту и VRAM — особенно при включенных **Ray Tracing / Path Tracing**, максимальных текстурах и других наиболее тяжелых графических настройках.

В таких сценариях может возникнуть нехватка свободной видеопамяти или GPU-ресурсов, что способно привести к снижению производительности игры или проблемам с генерацией.

**Рекомендация:** для комфортной работы оставляйте некоторый запас свободной VRAM. В обычных игровых сценариях, включая тяжелые игры на высоких/ультра-настройках, использование TTS в фоне не должно быть проблемой.

# Архитектура

## Twitch / Streamer.bot

Twitch не подключается к TTS Studio напрямую.

События Twitch получает **Streamer.bot**, который запускает соответствующий Action. Сгенерированный C#-код отправляет текст в API TTS Studio.

```text
┌──────────────┐
│    Twitch    │
└──────┬───────┘
       │ Twitch Events
       ▼
┌──────────────────┐
│   Streamer.bot   │
│                  │
│   C# Action      │
└────────┬─────────┘
         │
         │ POST /speak
         ▼
┌────────────────────────┐
│    Stream TTS Studio   │
│      FastAPI/Uvicorn   │
└───────────┬────────────┘
            │
            ▼
      ┌─────────────┐
      │ CosyVoice 3 │
      └──────┬──────┘
             │
             ├──────────────► WAV
             │                    │
             │                    ▼
             │              Streamer.bot
             │                    │
             │                    ▼
             │             CPH.PlaySound()
             │
             └──────────────► WebSocket
                                  │
                                  ▼
                              OBS Overlay
```

TTS Studio отвечает за генерацию речи и передачу события Overlay.

Streamer.bot отвечает за обработку Twitch-событий, выполнение C# Actions и воспроизведение полученного WAV.

---

## DonationAlerts

DonationAlerts использует отдельный путь.

TTS Studio самостоятельно подключается к DonationAlerts через **OAuth + Centrifugo WebSocket** и получает события о новых донатах.

После получения доната Studio вызывает HTTP API Streamer.bot:

```text
POST http://127.0.0.1:7474/DoAction
```

Streamer.bot запускает настроенный Action, внутри которого C# обращается обратно к TTS Studio:

```text
POST http://127.0.0.1:8765/speak
```

```text
┌─────────────────┐
│ DonationAlerts  │
└────────┬────────┘
         │
         │ OAuth + Centrifugo WS
         ▼
┌────────────────────────┐
│    Stream TTS Studio   │
└───────────┬────────────┘
            │
            │ /DoAction
            ▼
┌──────────────────┐
│   Streamer.bot   │
└────────┬─────────┘
         │
         │ C# Action
         │
         │ POST /speak
         ▼
┌────────────────────────┐
│    Stream TTS Studio   │
└───────────┬────────────┘
            │
            ▼
      ┌─────────────┐
      │ CosyVoice 3 │
      └──────┬──────┘
             │
             ├──────► WAV → Streamer.bot → CPH.PlaySound()
             │
             └──────► WebSocket → OBS Overlay
```

Таким образом, DonationAlerts подключён непосредственно к Studio, а Streamer.bot используется для запуска Action и воспроизведения результата.

# TTS Pipeline

Перед передачей текста в CosyVoice 3 Studio выполняет предварительную обработку:

* очистка URL и нежелательных символов;
* нормализация текста;
* обработка отдельных числовых значений;
* нормализация повторяющейся пунктуации;
* разбиение длинного текста на предложения.

Каждый фрагмент генерируется отдельно, после чего аудио собирается обратно в единый WAV.

Между предложениями добавляется небольшая пауза, а начало и конец отдельных фрагментов дополнительно сглаживаются.

Это позволяет удобнее работать с длинными сообщениями и не ограничиваться одной большой генерацией.

# Голосовые персонажи

Каждый персонаж хранится отдельно:

```text
characters/
└── <character_id>/
    ├── voice.wav
    └── avatar.png
```

Для персонажа можно настроить:

* голосовой референс;
* текст референса;
* скорость речи;
* аватар;
* активность персонажа.

### Подготовка референса

Встроенный редактор позволяет:

1. загрузить аудио или записать его с микрофона;
2. выбрать нужный участок;
3. обрезать запись;
4. нормализовать громкость;
5. очистить голос с помощью **Demucs**;
6. автоматически распознать текст через **faster-whisper**;
7. вручную скорректировать транскрипцию;
8. сохранить готовый референс;
9. сразу проверить результат через TTS.

Можно в любой момент восстановить оригинальный файл.

# OBS Overlay

TTS Studio содержит собственный Browser Source Overlay для OBS.

После генерации речи Studio отправляет событие через WebSocket:

```text
ws://127.0.0.1:8765/ws/overlay
```

Overlay получает информацию о персонаже, тексте и длительности реплики и отображает её на экране.

Поддерживаются:

* аватар персонажа;
* расположение аватара слева / справа;
* цвета;
* прозрачность;
* задержка скрытия;
* форма блока;
* рамка и визуальные эффекты;
* встроенные и пользовательские шрифты;
* размер текста;
* анимации появления / исчезновения;
* тестовый режим.

URL Browser Source и инструменты калибровки доступны непосредственно из Dashboard.

# Streamer.bot

Для Streamer.bot предусмотрен встроенный генератор C# Actions.

Поддерживаются следующие типы:

```text
tts
follow
raid
donate
```

Генератор позволяет настроить:

* максимальную длину сообщения;
* случайные или фиксированные фразы;
* `{user}`;
* `{streamer}`;
* количество зрителей;
* текст доната;
* сумму и валюту;
* склонение числительных;
* очистку текста перед отправкой в TTS.

Для TTS Action схема работы выглядит так:

```text
Twitch Event
     │
     ▼
Streamer.bot Action
     │
     ▼
C# → POST /speak
     │
     ▼
TTS Studio
     │
     ▼
CosyVoice 3
     │
     ▼
WAV
     │
     ▼
C# → CPH.PlaySound()
```

Для каждого типа события можно сгенерировать готовый код прямо из Dashboard.

# DonationAlerts

В Dashboard доступны настройки интеграции DonationAlerts:

* Client ID;
* Client Secret;
* Streamer.bot URL;
* имя Streamer.bot Action.

Callback:

```text
http://127.0.0.1:8765/api/da/callback
```

Studio получает данные доната и передаёт их в Streamer.bot Action:

* пользователь;
* сумма;
* валюта;
* сообщение;
* исходный текст.

Поддерживается обработка валют:

```text
RUB
USD
EUR
KZT
BYN
```

с автоматическим склонением суммы.

# HTTP API

TTS Studio запускает собственный локальный HTTP-сервер на FastAPI/Uvicorn.

По умолчанию:

```text
http://127.0.0.1:8765
```

### Generate TTS

```http
POST /speak
Content-Type: application/json
```

Пример:

```json
{
  "text": "Привет! Это тестовая генерация.",
  "character": "mita",
  "speed": 1.0
}
```

Ответ — WAV-файл.

### Swagger

```text
http://127.0.0.1:8765/docs
```

### Overlay WebSocket

```text
ws://127.0.0.1:8765/ws/overlay
```

## Основа проекта

Проект изначально создавался на базе готовой portable-сборки CosyVoice 3:

**mortimerme/repocollect — cosyvoice3-0529.7z**

https://huggingface.co/mortimerme/repocollect

Именно эта сборка была исходной точкой для локального запуска CosyVoice 3.

В дальнейшем вокруг неё была построена собственная TTS Studio с WebUI, подготовкой голосовых референсов, обработкой аудио, длинной генерацией, HTTP API, OBS-оверлеем и интеграциями со Streamer.bot и DonationAlerts.

То есть проект сохраняет исходную идею **локальной portable-сборки**, но добавляет поверх неё необходимую для стриминга инфраструктуру.

## RTX 50 / SM_120

Исходная portable-сборка не поддерживала архитектуру **SM_120**, поэтому для работы на RTX 50-й серии потребовалось обновить CUDA/PyTorch-окружение.

Текущая конфигурация разработки:

```text
GPU:       NVIDIA GeForce RTX 5080
Compute:   SM_120
PyTorch:   2.7.1 + cu128
CUDA:      12.8
```

После обновления CUDA/PyTorch установленный ONNX Runtime остался с доступным только CPU Execution Provider:

```text
Available providers:
AzureExecutionProvider
CPUExecutionProvider
```

Поэтому соответствующая вспомогательная часть окружения работает на CPU.

Основной TTS-инференс CosyVoice 3 при этом выполняется через PyTorch/CUDA.

ONNX Runtime не является основным вычислительным компонентом генерации речи, поэтому в текущей сборке его GPU Execution Provider отдельно не форсируется.
