## S1. Хранилище данных

**Проблема.** `save_*` открывают файл в режиме `"w"` (обрезают до записи), `load_*` при любой ошибке молча возвращают дефолт. Если `presets.json` читается в момент записи или повреждён, следующий `api_save_character` сохранит словарь из одного персонажа и затрёт остальных. То же для `da_tokens.json` (потеря refresh-токена).

**Куда.** Новый `server/studio/core/storage.py` (создать `server/studio/__init__.py` и `server/studio/core/__init__.py`). Затем заменить вызовы в `app.py`.

**Задачи.**
- [x] Создание `.gitignore` и правила исключения пользовательских данных выполнены в S1; повторно создавать файл не требуется.
- [x] `read_json(path, default, *, strict)`: при ошибке парсинга сначала пробовать `path + ".bak"`; для `presets.json` при двойной ошибке поднимать `StorageError`; для config/DA возвращать дефолт, **не перезаписывая файл**, с предупреждением в лог.
- [x] `write_json_atomic(path, data)`: временный файл в той же папке, `flush`, `os.fsync`, перед заменой копия предыдущей валидной версии в `.bak` (одно поколение), затем `os.replace`. На Windows при `PermissionError` повторить до 3 раз с паузой 50 мс.
- [x] Для каждого файла использовать `threading.Lock` вокруг короткого синхронного участка «прочитать → изменить → записать» в `api_save_character`, `api_delete_character`, `api_set_active`, `api_save_system_config`, `api_save_da_config`, DA-callback, `refresh_tokens`. Внутри участка не должно быть `await`. Не использовать `threading.RLock` как защиту между корутинами одного потока: он реентерабелен для одного потока. В async-эндпоинтах сначала выполнить необходимые `await` (например, чтение `UploadFile`), затем войти в синхронный блок под локом.
- [x] Эндпоинты, использующие presets, при `StorageError` отвечают 503 с понятным текстом (`/speak` включительно), а не пустым словарём.
- [x] Формат файлов прежний: UTF-8, `ensure_ascii=False`, `indent=2`, те же имена.

**Тесты** (`tests/test_storage.py`, без GPU): запись прервана исключением до `replace` → прежний файл цел; повреждённый файл читается из `.bak`; чтение во время цикла записей (стресс-тест из потоков) всегда возвращает валидный JSON; повреждённый `presets.json` не затирается.

**Приёмка.** Сценарии Dashboard (создать/сохранить/удалить/выбрать персонажа, сохранить настройки, авторизация DA) работают как раньше.

## S4. DonationAlerts worker

**Куда.** `DonationAlertsWorker` (`run_loop`, `send_to_streamerbot`, `get_access_token`, `refresh_tokens`), `api_test_da_donation`, обработчик тестовой кнопки в `web/dashboard/app.js`.

**Проблемы.** Синхронные `requests` внутри `async` (4–10 с на вызов блокируют весь сервер). Необработанная ошибка (payload не dict, `float(amount)`, `json.loads(action)`) приводит к реконнекту и потере доната. Повторов и журнала нет. При 5xx/429 показывается «Требуется авторизация». Выключение слушателя срабатывает только после следующего сообщения.

- [x] Все синхронные HTTP-вызовы в `run_loop` обернуть в `await asyncio.to_thread(...)`.
- [x] `get_access_token` вернуть профиль вместе с токеном, убрать повторный запрос профиля.
- [x] Вынести `parse_donation(payload) -> dict | None` с проверкой типов (dict, JSON-строка, список, `None`); `amount` приводить безопасно (замена запятой); некорректное событие логируется и пропускается **без реконнекта**.
- [x] `send_to_streamerbot` возвращает `{success, status_code, error, attempts}`. Payload строить внутри `try`. Повтор **один раз при ошибке установки соединения** (`ConnectionError`) и при HTTP 5xx; при таймауте чтения повтор не выполнять. HTTP 4xx не повторять. Для 5xx владелец согласовал повтор, так как текущий `/speak` формирует WAV до ответа и возвращает 5xx при неудачной генерации. `timeout=(3, 4)`. При не-2xx писать в лог первые 300 символов тела.
- [x] Неудачные отправки добавлять в `logs/streamerbot_failed_donations.jsonl` (блокировка записи, UTF-8).
- [x] `/api/da/test_donation` при неудаче отвечает 502 с `detail` (`message`, `status_code`, `error`); в `app.js` разбирать ответ безопасно (не падать на не-JSON) и показывать причину.
- [x] Backoff реконнекта 5→10→30→60 с, сброс после успешного подключения. Различать: нужна авторизация (401 после неудачного refresh) и DA временно недоступен (сеть, 5xx, 429).
- [x] Проверка `enabled` без ожидания сообщения: `asyncio.wait_for(ws.recv(), timeout=5)` в цикле.
- [x] `refresh_tokens`: логировать причину отказа (без секретов), сохранять токены через `write_json_atomic`.

## S5. Безопасность

Основные меры реализованы в `server/studio/routes/donations.py`, `server/studio/core/validation.py`, `server/studio/services/text.py` и frontend. Список ниже отражает текущий статус, а не первоначальный план.

- [x] **Callback (`api_da_callback`).** Внешние `error`, `resp.text` и `str(e)` экранируются через `html.escape`.
- [x] **Оверлей и превью.** Внешний текст выводится как текст, а не HTML; URL в тексте, отправляемом в Overlay, заменяются на «ссылка». Регрессионные проверки безопасного рендера и UI сохранены.
- [x] **Секрет.** GET `/api/da/config` не раскрывает сохранённый `client_secret`, возвращает `client_secret_set`; пустое/отсутствующее поле POST не затирает существующий секрет.
- [x] **Проверка Origin.** Для изменяющих HTTP-запросов и WebSocket при наличии `Origin` выполняется нормализованная same-origin проверка; без `Origin` запросы от небраузерных клиентов допускаются. IPv4/IPv6 и стандартные порты покрыты тестами.
- [x] **CORS.** Wildcard `allow_origins=["*"]` отсутствует. В `server/app.py` разрешён конкретный `monitor_origin`; для изменяющих HTTP-запросов и WebSocket действует отдельная нормализованная same-origin проверка при наличии `Origin`.
- [x] **OAuth `state`:** криптографически случайное одноразовое значение в памяти с TTL 10 минут; callback удаляет state при проверке.
- [x] **`char_id`.** Общий `require_character(char_id)` проверяет формат `[a-z0-9_-]+` и наличие персонажа в `presets`; используется инструментальными endpoints, которым нужен существующий голос. `get_active_overlay_config` не строит путь по произвольному `char_id`: аватар формируется только если ID есть в `presets` и проходит regex; для неизвестного ID используется тема по умолчанию.

### Входное аудио: единый путь через FFmpeg (2026-11-15)

Статический аудит выявил расхождения декодирования (`soundfile` в обрезке не читает M4A/WebM и брал только левый канал; запись с микрофона помечала WebM/Opus как `audio/wav`). Решение:

- Исходник хранится в браузере как есть (любой формат из `audio/*`); жёстких лимитов на длительность и размер нет — пользователь выбирает фрагмент из длинной записи.
- Обрезка, нормализация, тест TTS и сохранение персонажа используют один путь: `convert_to_clean_wav()` — FFmpeg, WAV mono 24 kHz PCM16, смешивание каналов, обрезка `-ss/-t` (длительность результата проверена на WAV/MP3/M4A/WebM/OGG). Ошибка чтения файла (`AudioDecodeError`) → HTTP 400, отсутствие FFmpeg/таймаут → ошибка сервера.
- Запись с микрофона и очистка Demucs удалены как функции (польза Demucs на практике не подтвердилась, запись заменяется загрузкой файла).
- Нормализация обрабатывает весь файл, а не регион; при длинном файле и коротком регионе UI предупреждает об этом.
- Откат: стек версий (6 шагов, Ctrl+Z) хранит блоб, текст референса и регион; «Исходный звук» — полный сброс.

Первым действием в `app.py`, до импорта любых собственных пакетов и `studio.core.env`, выполнить bootstrap стандартными модулями:

```python
import os
import sys
SERVER_DIR = os.path.dirname(os.path.abspath(__file__))
sys.path.insert(0, SERVER_DIR)
```

Это обязательно для embeddable Python: каталог скрипта не добавляется в `sys.path` автоматически. После bootstrap импортировать `studio.core.env`, выставить переменные окружения до импорта `torch`. Существующий `sys.path.append(COSY_DIR)` сохранить без изменения.

Импорты внутренних модулей выполнять через пакет `studio`, например: `from studio.services.text import sanitize_text`. Не создавать `server/core`, `server/services` и `server/routes` как верхнеуровневые пакеты.

В portable runtime в `sys.path` присутствует `cosyvoice` и его подпапки видны как модули верхнего уровня. Поэтому запрещено создавать собственные верхнеуровневые модули/пакеты с именами, совпадающими с подпапками CosyVoice: `utils`, `cli`, `flow`, `llm`, `transformer`, `hifigan`, `dataset`, `tokenizer` и аналогичные. Перед созданием любого нового верхнего import-имени проверять его через `importlib.util.find_spec` именно в portable Python. По текущей проверке имена `studio`, `core`, `services`, `routes`, `tests` свободны, `utils` занято (`cosyvoice/utils`).

Порядок переноса: `studio.services.text` → `studio.core.storage/config` → `studio.core.ws` → `studio.services.da_worker` → `studio.services.audio_tools` → `studio.services.tts_engine` → `studio.routes`. ## S9. FastAPI lifecycle (низкий приоритет)

Сейчас `server/app.py` использует два устаревающих обработчика:

Перейти на `FastAPI(lifespan=...)`, предварительно сверив API с фактической версией FastAPI в portable runtime. Сохранить поведение запуска и остановки worker, включая корректную отмену задачи.
