## Важное уточнение о поставке и проверке

Актуальная рабочая ветка разработки — `dev_test`; документация ниже описывает состояние этой ветки. `dev` ранее получала изменения из `dev_test` через merge, после чего разработка продолжилась в `dev_test`. Поэтому сравнение веток нужно трактовать с учётом уже выполненных интеграций, а не как две полностью независимые линии. Изменения `audio-cleanup` интегрированы через PR #4; `main` не затрагивалась.
Код Stream TTS Studio загружается архивом GitHub и распаковывается непосредственно в корень установки. Portable runtime (Python, CosyVoice, ML-библиотеки, модели и инструменты) находится рядом с кодом в каталоге `cosyvoice3\` и не входит в Git-репозиторий. Владелец может вручную проводить тесты и изменять файлы после распаковки, поэтому локальная установка не обязательно полностью совпадает с содержимым исходного архива.
Снимок фактического portable runtime владельца от 2026-11-15: [версии, модели и inventory](PORTABLE_RUNTIME.md).

Владелец проекта сообщил, что приложение уже проверено многими часами реальных стримов: генерация аудио работает, а связка OBS и Streamer.bot используется в рабочем процессе. Это важное эксплуатационное свидетельство владельца, но не результат независимого запуска текущей копии репозитория аудитором.

## Принцип дальнейшей разработки
**Не ломать работающий эфирный тракт.** Сохранить portable runtime и его версии, команды запуска, существующие API/payloads, пути и форматы пользовательских данных, поведение OBS Overlay, C# Actions Streamer.bot и сценарии генерации. Улучшения выполнять малыми изолированными изменениями, сначала покрывая существующее поведение тестами/контрольными сценариями, затем меняя реализацию и повторяя проверки.

Никакая задача из ROADMAP не является разрешением на массовый рефакторинг или миграцию runtime. Изменение публичного контракта или формата данных требует отдельного обоснования, миграции, плана отката и явного согласования.

## Правила редактирования исходников

- Код и текстовые файлы репозитория сохранять в UTF-8.
- Для `server/app.py` обязательно использовать окончания строк CRLF.
- Для остальных файлов сохранять уже существующий формат окончаний строк (CRLF или LF), не конвертировать файл целиком при точечной правке.
- Не выполнять массовое форматирование или изменение отступов вместе с функциональными исправлениями: diff должен отражать только намеренные изменения.
- Перед коммитом проверять diff на случайную смену окончаний строк и форматирования.

## Лицензирование и поставка

MIT License относится к оригинальному коду и документации Stream TTS Studio, но не заменяет лицензии компонентов исходной portable-сборки CosyVoice 3 [`mortimerme/repocollect — cosyvoice3-0529.7z`](https://huggingface.co/mortimerme/repocollect). Практическая инвентаризация основных компонентов и доступных сведений об их лицензиях собрана в [`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md) и [`PORTABLE_RUNTIME.md`](PORTABLE_RUNTIME.md). Python-окружение взято из исходного portable; отдельно владельцем установлен только `pywebview`.

Для standalone Gyan FFmpeg 7.1.1 сохранены идентификация архива и EXE, manifest зависимостей и build toolchain от сборщика, сведения о сборке и текст GPLv3 в [`licenses/ffmpeg/`](../licenses/ffmpeg/BUILD_INFO.md). Документация отражает всю информацию, которую удалось собрать в согласованном практическом объёме. Полная независимая проверка каждого файла исходного portable-архива и транзитивной зависимости не проводилась; неизвестные по доступным материалам детали остаются вопросами к исходной portable-сборке и её поставщику.

## Текущая оценка и открытые задачи

Основной пользовательский тракт, OBS, DonationAlerts и все четыре шаблона C# Builder подтверждены владельцем в реальной эксплуатации. A-11 по нормализации чисел реализована, CI и ручная акустическая проверка основных форматов пройдены; чтение `1-й` и `5-го` оставлено как известное некритичное ограничение. S7b, S8, S9 и дополнительные failure-mode проверки не являются обязательными задачами текущего релиза. Актуальные статусы: [AUDIT.md](AUDIT.md), [ROADMAP.md](ROADMAP.md), [REFACTOR_PLAN.md](REFACTOR_PLAN.md).

## Как читать результаты аудита
Различайте:
- **подтверждённое наблюдением кода** — например, конкретный способ вставки текста в DOM;
- **эксплуатационный факт со слов владельца** — длительная работа генерации и интеграций в реальной среде;
- **потенциальный риск** — зависит от конфигурации, доступности интерфейса и модели угроз;
- **непроверенное** — portable archive, runtime-зависимости и поведение на конкретной машине.

Аудит исходников сам по себе не доказывает нестабильность приложения. Backend уже разделён на `studio/core`, `studio/services` и `studio/routes`; `server/app.py` — компактный bootstrap/entrypoint (около 278 строк с учётом пустых строк и комментариев). В репозитории настроен GitHub Actions CI: compileall, pytest и JavaScript syntax checks. Синхронный I/O следует оценивать по конкретным измерениям, а не считать дефектом сам по себе.
