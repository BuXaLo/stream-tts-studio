# Безопасность и модель угроз

## 1. Предполагаемая среда

Приложение работает локально на Windows-ПК стримера. Код приложения находится в Git, а portable Python, ядро CosyVoice, ML-модули, модели и инструменты поставляются отдельно архивом и используются в изолированном окружении. OBS и Streamer.bot — штатные интеграции. По умолчанию backend слушает loopback.

Это не публичный multi-user backend. Меры защиты следует подбирать для локальной модели угроз и не превращать безопасные изменения в несовместимую перестройку системы.

## 2. Защищаемые активы и недоверенный ввод

Защищать:
- DonationAlerts client secret и OAuth access/refresh tokens;
- пользовательские голосовые референсы, аватары, настройки и пресеты;
- доступность CPU/GPU/RAM и диска;
- возможность запускать синтез и триггерить Streamer.bot actions;
- контент OBS Browser Source.

Недоверенный ввод:
- текст донатов/чата, имена авторов и прочие внешние строки;
- параметры OAuth callback;
- загружаемые аудио, изображения и шрифты;
- HTTP-запросы от локальных процессов и браузерных страниц.

## 3. Риски с наибольшей практической ценностью

### DOM XSS в Overlay
Весь динамический текст должен отображаться как текст, а не интерпретироваться как HTML. Предпочтительно `textContent` и безопасно созданные DOM nodes. Исправление не должно удалять анимации, темы, эффекты слов или менять визуальную композицию.

### Утечка DonationAlerts credentials
API не должен возвращать сохранённый `client_secret` или OAuth tokens. Для UI нужен отдельный флаг `has_client_secret`/статус, а не секрет. Обычное сохранение настроек не должно затирать уже сохранённый секрет пустой строкой. Токены остаются локальными; ограничить ACL каталога и исключить файлы из Git/логов.

### OAuth callback
Добавить криптографически случайный одноразовый `state` с ограниченным сроком действия и проверять его до обмена authorization code. Сохранять текущие понятные сообщения об ошибке и повторную авторизацию.

### Локальный API и CORS
Loopback снижает сетевую экспозицию, но не равен полной изоляции: локальные процессы и браузерные страницы могут обращаться к localhost. Wildcard CORS увеличивает поверхность доступа. Перед изменением нужно выяснить, какие origins реально используют Dashboard, Overlay и сторонние инструменты. CORS сам по себе не заменяет аутентификацию. Если будет добавлена авторизация, она должна быть совместима с OBS Browser Source и Streamer.bot и не требовать ручного ввода токена в каждом эфире.

### Загрузка файлов и ресурсоёмкие операции
Размер, длительность и тип файла проверять до тяжёлой обработки. Лимиты выбирать по существующим рабочим файлам и целевой машине. Не вводить ограничения, нарушающие типичные длинные референсы или аудио workflow.

## 4. Принципы безопасного внедрения

1. Не менять portable archive, системный/portable Python, CUDA, PyTorch, CosyVoice и версии ML-библиотек без отдельной необходимости и отдельного плана.
2. Не менять API paths, HTTP methods, JSON keys, WebSocket event schema, Streamer.bot C# Actions и OBS URLs в рамках исправлений безопасности.
3. Не менять формат и расположение пользовательских JSON/персонажей без миграции и резервной копии.
4. Сначала зафиксировать baseline и добавить проверки существующего поведения.
5. Каждое исправление — отдельный небольшой коммит в `dev`; проверка после каждого коммита.
6. При сбое — откатить только последний узкий коммит; не пытаться чинить несколько слоёв одновременно.
7. Все изменения сначала проверять на копии рабочей установки и тестовых данных, а не во время эфира.

## 5. Минимальный incident response

Если секрет попал в лог, API-ответ, публичный репозиторий или стороннему лицу:
1. отозвать/обновить соответствующий credential у провайдера;
2. удалить его из конфигурации/логов и проверить Git history, если он попадал в репозиторий;
3. проверить, не слушает ли сервер LAN/public interface;
4. повторно авторизовать DonationAlerts и проверить соединение;
5. не публиковать диагностические логи с токенами или персональными данными донатеров.

## 6. Текущий статус в `dev_test`

Реализовано в коде:
- Overlay и Dashboard preview строят динамические фрагменты через DOM nodes и `textContent`; имена персонажей в sidebar также вставляются как текст.
- GET `/api/da/config` не возвращает client_secret; POST сохраняет прежний секрет, если новое значение не передано.
- OAuth callback проверяет одноразовый `state` с TTL 10 минут; ошибки callback экранируются через `html.escape`.
- При наличии Origin проверяются изменяющие HTTP-запросы и WebSocket; сравниваются hostname/scheme/effective port, включая IPv6 и стандартные порты.
- Host/port и Streamer.bot URL валидируются; порт допускает полный диапазон 1–65535.
- Для аудиообработки заданы timeout FFmpeg и диапазоны параметров.

Ограничения:
- API не имеет полноценной аутентификации. Не выставлять его в интернет; для LAN bind осознанно оценить модель угроз.
- Лимиты размера upload-файлов не заданы: их нужно согласовать по реальным пользовательским файлам.
- Локальный portable runtime, OBS и Streamer.bot не проверялись в GitHub CI.

История находок и статус закрытия — в [AUDIT.md](AUDIT.md); порядок оставшихся работ — в [REFACTOR_PLAN.md](REFACTOR_PLAN.md).


## Desktop monitor

Маршруты мониторинга и WebSocket событий доступны только при loopback-адресе клиента и Host. Это ограничивает доступ к входящему тексту, журналу и команде выключения локальным компьютером, даже если основной сервер привязан к LAN-интерфейсу.
